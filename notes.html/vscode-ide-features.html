Introduction

VS Code's IDE capabilities are built on two protocols it originated as an editor client: LSP (Language Server Protocol) for code intelligence, and DAP (Debug Adapter Protocol) for debugging. Not every feature is available for every language — it depends on whether the specific language server or debug adapter implements that capability — but this is the full set VS Code itself supports as a client.

Part 1 — Language Intelligence

Editor Chrome Features

VS Code UI conventions built around LSP data — some are direct UI treatments of an LSP response, others are pure editor polish with no protocol request behind them.

Feature LSP-backed? Description
Peek Definition / Peek References ✓ Yes Shows the target inline in an expandable panel without switching editor tabs.
Breadcrumbs bar ✓ Yes Path › file › enclosing symbol navigation bar above the editor.
Problems panel ✓ Yes Centralized, filterable list of all errors/warnings across the project.
Sticky Scroll ✗ No Pins the current enclosing function/class/block header at the top of the viewport while scrolling.
Bracket Pair Colorization ✗ No Matches bracket pairs by color.
Minimap ✗ No Miniature file overview on the right edge of the editor.
Multi-cursor editing ✗ No Place and edit from multiple cursors simultaneously.
Quick Fix lightbulb ✓ Yes Visual indicator that code actions are available at the cursor.

Part 2 — Debugging

32 features

All debugging features backed by the Debug Adapter Protocol (DAP). These capabilities enable step-through debugging, breakpoints, variable inspection, and runtime control through communication between the editor and debug adapters.

#1

Launch/Attach configurations

DAP

Run and Debug view, configuration dropdown.

launch.json
#2

Line breakpoints

DAP

Click in the gutter next to a line number.

#3

Conditional breakpoints

DAP

Right-click a breakpoint → Edit Breakpoint → expression condition.

#4

Hit-count breakpoints

DAP

Right-click a breakpoint → Edit Breakpoint → hit count condition.

#5

Triggered breakpoints

DAP

Armed only after another breakpoint fires. Right-click gutter → Add Triggered Breakpoint.

#6

Function breakpoints

DAP

Break by function name, no source line needed. "+" button in the Breakpoints panel.

#7

Inline breakpoints

DAP

Column-specific, for multi-statement lines. Shift+F9, useful for minified/dense code.

#8

Data breakpoints

DAP

Break on variable value change/read/access. Right-click a variable in the Variables view.

#9

Logpoints

DAP

Log a message without pausing execution. Right-click gutter → Add Logpoint.

#10

Exception breakpoints

DAP

Checkboxes in the Breakpoints panel.

#11

Debug toolbar.

DAP
